# 附录 O.4 — 接口的往返缺陷（表 68）

对应书里两处：

- **O.4**「下面是一个真实跑出来的结果（**脚本与结果文件随书提供，固定随机种子，四万个样本**）」
- **O.9** 本章边界「**脚本与结果都随书提供，可自行改参数复现**」

## 文件

| 文件 | 是什么 |
|------|--------|
| `invariant_math.py` | 生成本章表 68 的脚本。单文件、无第三方依赖、只用标准库 |
| `invariant_math_results.txt` | 书中那次运行的**原始输出**（UTF-8，LF 行尾），表 68 的三个数就是从这儿取的四舍五入 |

## 复现

```bash
python invariant_math.py --out my_run.txt
diff my_run.txt invariant_math_results.txt      # 应当无输出
```

不需要联网，不需要 GPU，不需要模型。一次约两三秒。

脚本参数（默认值就是书中那次运行的参数）：

```
--M        样本数，默认 40000
--n-tasks  下层任务数，默认 4
--seed     随机种子，默认 20261006
--out      同时把输出写到文件，便于与存档结果 diff
```

`--M` / `--n-tasks` / `--seed` 这一层薄封装是发布时加的：逻辑与随机数调用顺序一字未改，只把三个常量提成了可选参数，好让 O.9 那句「可自行改参数复现」真的能照着做。默认参数下的输出与原始记录逐行一致。

## 表 68 的三个数怎么来的

模型：下层是四个任务，每个任务 = （状态，负责人）。状态取 待办 / 进行中 / 已完成，负责人取 甲 / 乙 / 丙 / 未指派。不变量 I = 「状态为进行中的任务，必须有负责人」。

两个候选接口：

- `π₁`：只上报各状态的计数（丢掉负责人）
- `π₂`：上报（状态，负责人）的多重集（丢掉顺序，保住负责人）

往返缺陷 `defect` = 在合规状态里，视图无法与某个违规状态区分的比例。四万样本上：

| 接口 | 往返缺陷 | 能否守住 I | H(视图)/bit |
|------|---------|-----------|-------------|
| π₁ 只报计数 | 0.8504 | 否 | 3.5274 |
| π₂ 带负责人 | 0.0000 | 是 | 8.9447 |

书里写作 0.8504 → 0.0000、3.53 → 8.94 bit。另外两个数：H(具体域) = 12.5115 bit，守住不变量的信息代价 = 5.4173 bit（书里写 5.42）。

## 这个实验证明了什么、没证明什么

**证明了**：往返缺陷是一个可计算的标量，接口改一改它就动；而且「守住不变量」有确切的信息代价，不是免费的。

**没证明**：任何真实系统上的绝对数值。四个任务、四万样本是一个**受控的玩具模型**——它的作用是让「泄漏」这个说法第一次有个数，不是去估计某个真实组织的泄漏率。换分布、换不变量、换任务数，0.8504 会变（这正是 `--M/--n-tasks` 存在的意思）。书里 O.9 已经这么写了，这里再写一遍。
